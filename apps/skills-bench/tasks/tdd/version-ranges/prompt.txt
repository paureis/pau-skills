release-tools needs to understand the version ranges in our manifests. Please add a new module src/range.js with an exported function satisfies(version, range) that returns true when a version such as "1.4.2" is inside a range, and add an exported function newestMatching(versions, range) to src/releases.js.

The ranges, with no space between an operator and its version:
- "1.2.3" or "=1.2.3" matches only 1.2.3.
- ">=1.2.0", ">1.2.0", "<=2.0.0" and "<2.0.0" mean what they say: ">=1.2.0" includes 1.2.0 itself, ">1.2.0" does not.
- "^1.2.3" allows 1.2.3 up to, but not including, 2.0.0. Below 1.0.0 the caret is tighter: "^0.2.3" allows up to, but not including, 0.3.0, and "^0.0.3" allows only 0.0.3.
- "~1.2.3" allows 1.2.3 up to, but not including, 1.3.0.
- Two of these separated by a space must both hold: ">=1.2.0 <1.5.0".
- satisfies takes a version with a leading "v", as parseVersion does: "v1.2.3" is inside "1.2.3".
- A range that cannot be read (such as "abc", "1.2" or "") throws a RangeError, and so does a version that cannot be read.

newestMatching returns the highest version in the list that is inside the range, written as it is in the list, or null when none is. The list can be in any order, and versions go by number: 1.10.0 is higher than 1.9.0.

Use parseVersion and versionOrder from src/version.js. Build it test first.
