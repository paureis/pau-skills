# Patch 0.23.0: batch 22, context in fewer calls

Files get split only where a real boundary is, and friction-review now measures whether scattered or oversized files
cost the agent turns, so the next change to the size limit can rest on numbers.

## :sparkles: New

- `friction-review` measures what scatters context: files read in pieces, new files made with Write, new files in
  commits over the days read, and the reads and searches before the first edit in each folder (median, maximum and
  the worst edits).

## :arrow_up: Changed (buffs and nerfs)

- `file-size-guard` (nerf to busywork splits): its refusal now says to split only along a real boundary and to leave
  one line saying where each part went. With no real boundary, the agent asks you for a per-path limit instead of
  moving code into a helpers file that exists only to stay under the limit. Data files keep their recipe.
- `lazy-senior` (buff): one more rule in every session and subagent: a new file needs a reason, and size alone is not
  one; extend the nearest file first and keep code that changes together in one place. It is not a rule against new
  files. Its always-on text grows from 1,532 to 1,772 characters (about 60 tokens per start), with your yes.
- `friction-review` (fix in the same batch): a shell command that writes a file (`cat > file <<EOF`) is not counted as
  a read, Windows paths are compared after resolving the project roots, and a failing `git log` no longer ends the
  report.

## :inbox_tray: What you do

  `claude plugin update pau-skills-hooks@pau-skills`.

  lines: they say whether files read in pieces or scattered across folders cost more turns.

## :warning: Known issues

- The test-file recipe still offers "a helpers module" while the new line warns against "a helpers file of
  leftovers"; only the words "of leftovers" tell them apart. A later item can narrow the recipe.
- friction-review sees edits made with Edit, Write, MultiEdit and NotebookEdit, not files changed through shell
  commands; the git line covers those over the whole date range.
- `skill-eval`'s trigger mode still counts typed-only skills as under test.
