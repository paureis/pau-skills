# Patch 0.26.0: between batches, a session stops at two compactions

A session now gets two compactions. The third is blocked, with a note that the session has already compacted twice
and should hand off.

## :sparkles: New

None.

## :arrow_up: Changed (buffs and nerfs)

- `compact-snapshot` (nerf to session length): once the session has compacted twice, the next compaction is blocked.
  The reason reads "This session has already compacted twice, its limit (maxCompactions in .claude/pau-skills.json).
  This compaction is blocked: finish the current step, write a handoff or the next kickoff, and tell the user to start
  a new session." Set `maxCompactions` to change the limit, or `0` for none.
- `compact-snapshot`: the hand-off line at the second compaction now adds that the next one will be blocked.
- `compact-snapshot`: the snapshot is still saved on a blocked attempt, so the facts are there if Claude Code compacts
  anyway at the hard limit of the context window.

## :warning: Known issues

- When the context window is completely full, Claude Code compacts even though the hook blocked it: the request
  cannot go out otherwise. The block was shown live with `/compact`; automatic compaction runs the same hook.
- If a blocked automatic compaction is tried again on later turns, each try saves a snapshot. Only the newest ten are
  kept.
- When another session wrote a newer snapshot, compact-snapshot shows no snapshot text at all (Q39 item 1).
