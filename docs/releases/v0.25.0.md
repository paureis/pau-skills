# Patch 0.25.0: batch 24, watchdog fixes and a compaction count

The subagent watchdog stops asking healthy agents whether they are stuck, and compact-snapshot now tells you when a
session has compacted often enough that a new one would serve you better.

## :sparkles: New

None.

## :arrow_up: Changed (buffs and nerfs)

- `subagent-watchdog` (fix): an edit counts wherever the file is. A builder working in a sibling worktree or in the
  scratchpad is no longer asked if it is stuck.
- `subagent-watchdog` (fix): a project or user agent whose definition lists its tools, with none of Edit, MultiEdit or
  NotebookEdit, is read-only and skips the no-edit rule. `readOnlyAgents` now adds to the built-in list instead of
  replacing it.
- `subagent-watchdog` (fix): an agent with a call in flight for two hours and no event since is dropped from the status,
  since it most likely ended without a stop event. An agent waiting on its own subagents is still never dropped.
- `subagent-watchdog` (wording): the main-session status says "running or just finished", and shows a top repeated
  command only when it ran at least twice.
- `compact-snapshot` (buff): it counts the compactions in the session. From the second one, the note tells the session
  to finish the current step, write a handoff or the next kickoff, and tell you to start a new session. Set
  `handoffAfter` to change when that starts, or `0` to turn it off. A snapshot from another session is neither shown
  nor counted.

## :warning: Known issues

- When another session wrote a newer snapshot, compact-snapshot shows no snapshot text at all. It should pick the
  newest snapshot from its own session. This is on the backlog.
- The read-only rule reads only the top level of `.claude/agents` in the project and in your home folder. A plugin's
  agents are not read, so list those in `readOnlyAgents` if they never edit.
