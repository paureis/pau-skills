# Patch 0.27.1: batch 26, three small follow-ups

Three things earlier reviews left behind: `rule-to-hook` knows the hook event for typed slash commands, the advice on
splitting files says the same thing in every place, and two hooks stop missing what is theirs.

## :sparkles: New

None.

## :arrow_up: Changed (buffs and nerfs)

- `rule-to-hook` (buff): HOOK-EVENTS.md has a row for `UserPromptExpansion`, the event that fires when a typed slash
  command or MCP prompt expands. Its matcher is the command name, and exit 2 blocks the expansion.
- `file-size-guard`: when it asks you to split a test file, it now says to add a helpers module only when two or more
  of the new files share the setup.
- `lazy-senior`: a review now flags a new file that holds what an existing file could.
- `geppetto` roster: the builder carries the rule on new files (roster 8). Run `geppetto` again to update installed
  agents.
- `compact-snapshot` (buff): after a compaction, the note shows this session's newest snapshot, even when another
  session in the same project saved a newer one. Fixes the known issue from 0.26.0.
- `subagent-watchdog` (buff): a README or notes file with no frontmatter in an agents folder no longer makes every
  agent after it count as one that edits. Claude Code does not load such a file as an agent. Fixes the known issue
  from 0.25.0.

## :warning: Known issues

- `subagent-watchdog` reads agent files more strictly than Claude Code. A file Claude Code still loads, such as one
  with an unclosed list `tools: [Read, Grep`, makes the agents after it count as ones that edit. Subfolders of an
  agents folder are not read. Both err on the cautious side (Q42).
- `compact-snapshot`: a stray `.md` file in the snapshots folder whose name is not a timestamp sorts as the newest and
  is shown instead of this session's snapshot. Snapshot files are named by the hook, so this only happens when a file
  is put there by hand.
