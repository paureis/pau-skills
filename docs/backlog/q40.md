# Q40 rule-to-hook knows the events added since its table was written

[Back to the backlog index](../BACKLOG.md)

**Q40 rule-to-hook knows the newer hook events** (`todo`, found 2026-11-27 in the Q34 plan check). The events table
in `skills/guards/rule-to-hook/HOOK-EVENTS.md` has 14 rows. Claude Code 2.1.332 lists 34 hook events, among them
`PostToolUseFailure`, `PostToolBatch`, `StopFailure`, `PostCompact`, `PermissionDenied`, `ConfigChange`,
`InstructionsLoaded`, `FileChanged` and `CwdChanged`. A rule that should fire when a tool call fails (for example
"after a failed test run, read the output before retrying") has no row to point at.

Add a row for each event a rule is likely to need, at least `PostToolUseFailure`, `StopFailure` and `PostCompact`,
each checked against the installed binary for its input fields, matcher and what exit 2 does, as Q34 did. Leave out
events no rule would use, and say in one line that the table is not the full list.

Done when each new row has a test that fails without it, and the guards plugin is bumped.
