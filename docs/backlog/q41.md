**Q41 a roster bump forgotten everywhere** (`done` 2026-11-27, pull request 106; found 2026-11-27 in the Q36 review). The geppetto tests compare
each covenant marker's roster number with the one in `COVENANT.md`. If a change to a roster agent leaves all 12
markers at the old number, every test still passes: the reviewer set all of them back from 8 to 7 and 47 tests
passed. Only a grep showed the bump had happened.

Possible fix: a test that the roster number goes up whenever a roster file differs from the last release, for example
by keeping the roster number with a hash of the roster files in one checked-in line, so a changed file with the same
number fails.

Done when that test fails on a roster edit with no bump (mutate.sh), and passes on the current tree.

Built in the twenty-seventh batch as `tests/geppetto-roster-lock.test.mjs`: `LOCK` holds the roster number and a
sha256 of every file under `roster/` (dot entries skipped, marker numbers masked), and each failure says the exact
`LOCK` value to set. With all 12 markers set back to 7, the geppetto tests went from 43 passing to 1 failing of 53.
