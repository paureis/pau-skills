# Q17 descriptions that start their skill

[Back to the backlog index](../BACKLOG.md)

**Q17 descriptions that start their skill** (`in progress`, scope settled in decision 19). The first trigger round (Q16,
`evals/triggers/baseline.md`) found no wrong starts and 175 hits in 228 runs. 41 of the 53 misses ran a Bash command
in the empty folder first and ended at the one-turn limit, so the round cannot yet tell a weak description from an
agent that looks before it chooses. Q17 settles that first, then rewords the descriptions that still miss.

## Part 1: how much the one-turn limit costs

- `skill-eval.mjs triggers` gets `--max-turns <n>` (default 1, at most 3) and a way to run only some requests: a
  folder of lists that holds a subset is enough, since the mode takes any number of requests per list; the repository
  test asks for 3 and 2 only in `evals/triggers/requests/`. The first Skill call in any of the turns counts; the
  summary records the turn it came in.
- Rerun the 41 "after Bash" misses of the baseline with two turns, 1 repeat (approximately 4 to 7 US dollars; the
  estimate goes to the owner before the run). A miss that hits in turn 2 is a one-turn effect, not a weak
  description.
- The result goes in `evals/triggers/baseline.md` under its own heading.

## Part 2: reword the descriptions that still miss

- The candidates from the baseline: `codebase-oracle` and `parallel-worktrees` (0 of 6), `bug-fix`,
  `lean-subagent-dev`, `sharpen` and `to-prd` (2 of 6), `arena`, `evaluator`, `overnight-run` and `retrospective`
  (3 of 6). Part 1 decides which stay on the list.
- Each rewrite keeps the rules of "Policy since P0.5" (`docs/backlog/context-budget.md`): at most 400 characters, all
  descriptions together at most 14,000, the trigger-list form, and quoted phrases only for phrases that ask for the
  work on a confirm-list skill. A changed request-1 phrase changes the skill's request list: the list test checks it.
- A request in a list never changes to fit a description: the lists stay the yardstick.
- Then one full round with `--baseline evals/triggers/baseline` (380 runs, approximately 34 US dollars, cap 40; the
  estimate goes to the owner first). Done when no skill has a wrong start, every near miss stays right, and the hits of
  each reworded skill go up, or the pull request says why one did not.

## Done when

- Part 1 is built test first, proven with `mutate.sh`, and the four repository checks pass.
- Both paid runs ran within their estimates, and their summaries are committed as parts next to the baseline.
- Versions: `skill-eval` (verification) gets a minor bump, and each plugin whose skill description changed a patch
  bump, with the bundle. The owner gets the zips of every changed skill.

## Changed in the orchestrator's review before the build (2026-11-04), and why

Checked against the code at 1e72f06 and the baseline parts in `evals/triggers/baseline/`.
- **The rerun is the 41 runs, once each.** The 41 "after Bash" misses are 26 requests: 15 missed in both repeats and
  11 in one. The subset lists go in `evals/triggers/two-turn/requests/<skill>.json`, with only `should` requests, the
  text exactly as in the baseline, and a request that missed twice listed twice; the round runs with `--repeats 1`,
  so it makes exactly 41 runs. The mode already takes duplicate requests and lists with no near misses. A test checks
  that the folder holds exactly the baseline's "looked first" misses, as many times as each missed.
- **The turn of a start** is counted from the transcript: the number of distinct main-agent assistant message ids up
  to and including the one with the first Skill call. The first rerun transcripts confirm it for free, as batch 13
  did. The summary gets `maxTurns` (a baseline without it reads as 1) and a `turn` per run (null when nothing
  started); the report shows the turn of each hit when `maxTurns` is above 1.
- **The rerun's price**: a second turn reads the cached prompt and adds about 0.02 to 0.04 US dollars, so it runs with
  `--usd-per-run 0.12` (estimate 41 x 0.12 = 4.92) and a cap of 7, about one hard stop per parallel run above it.
- **Which skills Part 2 rewords.** A turn-2 hit in the rerun counts as a hit. A candidate stays on the list while it
  still has 2 or more misses of 6 after that; `lean-subagent-dev` had no miss after Bash (all 4 answered in text), so
  the rerun cannot remove it. Skills outside the ten that still miss 2 or more are named in the pull request for the
  owner, not reworded.
- **Request 1 stays in each description.** The owner's rule wins over the line above that let a changed request-1
  phrase change the list: every rewrite keeps its request-1 phrase quoted, word for word, as the first quoted phrase
  after "Use when", and no list changes.
- **The rewriter never sees the lists.** A description tuned to the requests would make the round measure the fit,
  not the description. The builder reads the skill bodies, the current descriptions, the rules and, per skill, the
  counts of its misses by kind (answered in text, looked first, still none after two turns), never
  `evals/triggers/requests/`, `two-turn/` or the baseline parts. `tests/trigger-lists.test.mjs` already fails when a
  description quotes a phrase that a request 2, 3 or near miss holds, without quoting the phrase.
- **The full round keeps one turn**, as the baseline did, so the comparison holds; the pull request says, per reworded
  skill, how many of its remaining misses looked first. Its parts go in `evals/triggers/after-q17/`.
- **Room left**: `skill-eval-triggers.mjs` is 18,884 bytes and `SKILL.md` 18,684, so the turn counting goes in
  `skill-eval-triggers-count.mjs` and the new tests in a new test file. The descriptions total 13,101 of 14,000.
- The CHANGELOG entries of ISO week 44 move to `docs/changelog/2026-W44.md` before this batch's entry.

## Changed during the build (plan checks, reviews and fix rounds), and why

- `eng-lead` planned two slices: A (the option, the turn of a start, the two-turn lists) in full, and B (the rewording)
  as a draft with two fields the orchestrator filled after the rerun. B went to a fresh builder that never read the
  lists, and B's plan check and review were kept from `evals/` too.
- The A plan check built the slice in a clone: all 15 planned mutations were caught, and nine of its own survived,
  among them a turn rule that counted messages after the first Skill call (real two-turn runs go on after a start), an
  untested `Hits by turn: none` and an unpinned one-turn report. All nine went into the brief before the build. The A
  review then found no defect; its own 20 mutations were caught.
- The rerun found no turn-2 start (see `evals/triggers/baseline.md`), so all ten candidates were reworded.
- The B plan check found that test output could show request text (a failing assertion prints both values), that
  curly quotes and a backticked skill name followed by "if installed" pass every test, and that no test holds the
  confirm-list quoting rule or the "Use ..." opener. The brief then sent all test output to a file read only through a
  grep, added checks for backticks and curly quotes, kept every opener, and the orchestrator ran a blind check of every
  quoted phrase against every list (0 collisions; a control phrase found 114).
- The B review found two low defects (to-prd listed the body's section headings; retrospective promised one edit per
  correction); one fix round fixed both. The builder added no new quoted phrase: new wording went into unquoted
  situations.
- `docs/REFERENCE.md` says the trigger mode can run up to three turns. The CHANGELOG entries of week 44 moved to
  `docs/changelog/2026-W44.md`, and `context-budget.md` says the confirm list holds 14 skills (it said 13).

## Results

- Part 1: 41 two-turn runs for 4.49 US dollars (estimate 4.92, cap 7). No skill started in turn 2.
- Part 2: the full round for 34.67 US dollars (estimate 30.40, cap 40): no wrong start, 152 of 152 near misses right,
  186 hits of 228 (175 before). Six reworded skills went up (`arena` 3 to 6, `overnight-run` 3 to 5, `codebase-oracle`
  and `parallel-worktrees` 0 to 2, `evaluator` and `retrospective` 3 to 4). Four did not: `bug-fix`,
  `lean-subagent-dev`, `sharpen` and `to-prd` stayed at 2 of 6, missing on the same requests as before, either with a
  text answer (the agent did the work in its reply) or after looking around the empty folder. Six skills whose
  descriptions did not change moved by 1 or 2 either way, so a change of that size for one skill is within run to run
  variation.
- Still missing 2 of 6 outside the ten, not reworded: `architect`, `engineering-principles`, `hillclimb`, and
  `migration-review` (6 before; its description did not change).
