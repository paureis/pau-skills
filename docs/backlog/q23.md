**Q23 the lazy senior developer** (`built`, seventeenth batch, on the branch `claude/practical-mayer-uriy9l`; decision 25). The owner asked to bring the method of ponytail
(<https://github.com/DietrichGebert/ponytail>, MIT, Copyright (c) 2026 DietrichGebert, read at commit

## What ponytail is, and what its evidence supports

One prompt (`skills/ponytail/SKILL.md`, 3.5 KB) that a SessionStart and a SubagentStart hook inject in every session
and subagent, plus a review and an audit skill, a `shortcut:` debt ledger, a benchmark scoreboard, a help card, a cost
band above the prompt and packaging for twenty agent tools. Its hooks only add context (no block, no `updatedInput`).

The core, worth taking:
- **The ladder**, before writing code, stopping at the first rung that fully works: does it need to exist; is it already
  in this codebase; does the standard library or the platform do it; does an installed dependency do it; can it be one
  line a reader gets at a glance; only then the minimum code that works.
- **Lazy about the solution, never about the change**: read the code the change touches first, list every caller, test,
  fixture, config and export it must reach, and finish all of them. On a bug fix, grep every caller and fix the shared
  function once (the only wording that moved its caller-tracing benchmark task).
- **Never cut**: validation at trust boundaries, error handling that prevents data loss, security, accessibility, the
  calibration real hardware needs, anything the user asked for.
- New non-trivial logic leaves one small test; a known limit gets `shortcut: <the limit>, <when to upgrade>`; every
  reply ends with what was skipped or not checked and any risk.
- **The review and the audit** (ponytail 5): order correct, safe, holds under the expected load, tested, fast, lean;
  read the callers, not only the diff; state the load assumed; every finding needs a concrete case; four parts per
  finding (what this is, problem, fix, if we skip it); Must fix, Should fix, Nice to have, numbered; a verdict; a lean
  line count; a "not checked" line. Lean: delete, reuse, standard library or native, yagni, merge, split by job.

What its own results support (`benchmarks/results/`, checked by a subagent on 2026-11-16): on open-ended feature work it
writes much less code, mostly by using the platform (a date picker in 23 lines through `<input type=date>`); across 39
tasks on Opus 5.5, -53% code, -26% cost, -41% time, with correctness and safety level with no skill. Against it: its
tests catch fewer injected bugs (69% against 77%), a blind judge leaned to the no-skill replies (106 to 82), small
surgical tasks cost more on 8 of 38, and it did worse on other model families. The raw data is not in the repository.
Two of its featured examples are unsafe by its own safety benchmark: an email regex that accepts a newline, a CSV one-liner
that crashes on a malformed row. So the method is taken, not the numbers, and our examples are written fresh and safe.

## Decided (decision 25)

1. **One new skill, `lazy-senior`**, in the `planning` plugin, with three modes in bundled files: build (the ladder,
   the never-cut list, the finish-the-change rules), review (a diff, in ponytail 5's order, lean last) and audit (the
   whole repo). A `shortcut:` debt ledger, with a Node standard library script that is language-neutral about comment
   prefixes. Fresh, safe before-and-after examples in a bundled file, covering the platform, the standard library, an
   installed dependency, deletion and a guard kept. It works on its own; its description fits the 408 characters left.
2. **One new hook, `lazy-senior`**, on by default, in a new `hooks/planning/`: SessionStart (startup, resume, clear,
   compact) and SubagentStart add a short ruleset (about 1 KB) as context. The text opens with "when you write or
   change code", so a read-only agent is not told how to build. Off with `"hooks": {"lazy-senior": false}` or
   `PAU_SKILLS_DISABLE`. One source for the text, with a test that the skill's copy and the hook's copy match. If the
   measurement in 5 shows harm, the default becomes off and the owner is told.
3. **The same rules everywhere**: the builder agent gets the ladder and the finish-the-change rules; the reviewer agent
   gets a last check, "bigger than needed", with a concrete case required; both through `geppetto`'s roster first,
   with the roster number raised. `review-triage`'s `TRIAGE.md` (both copies) treats a needless layer, option or
   dependency the change itself added as fix if cheap, and a `shortcut:` comment that names its limit as a decision.
   `engineering-principles` gains "use what already exists" (standard library, platform, installed dependency before
   new code) inside "Subtract before you add". `which-skill` routes "this is over-engineered", "write the simplest
   version" and "review for bloat" to it.
4. **Skipped**, with the reason: the gain scoreboard (its numbers, not ours), the help card (`which-skill` covers it),
   the cost band, board and statusline (a separate tool), the level modes (lite, full, ultra; one rule set is enough
   until a need shows), the in-prompt `/ponytail` commands and "stop ponytail" phrases (the config switch does it), the
   codebase map injected at session start (a git process and 2 KB in every session; possible later), packaging for
   other agent tools, and its benchmark harness (`skill-eval` does that job here).
5. **Measured before it ships**: a small `skill-eval` run, with and without the skill, blind-judged, on a small model
   with `--max-budget-usd`; the owner gets the estimate first.

## Changed during the build (plan checks, reviews and fix rounds), and why

- `eng-lead` planned three slices: A the skill and the hook, B the same rules in the roster, review-triage and
  engineering-principles, C a test that the copies agree (after A and B). The description was capped at 340
  characters (337 used, 71 of the 14,000 left).
- The plan check of A built it in a clone: the suggested ruleset was over its own cap; `debt.mjs` as briefed crashed on
  deleted paths, submodules and big repositories, had a quadratic path and a marker rule that missed a dozen comment
  forms; and three lines were unsafe (a `shortcut:` comment could excuse a security cut, "keep the platform's form"
  allowed money as a float, nothing forbade a hand-rolled sanitizer or parser). All fixed in the brief.
- The plan check of B found that a `shortcut:` comment could send a security finding to Leave, that the reviewer check
  could flag what the contract asked for, and that the triage rule contradicted the rest of TRIAGE.md. Fixed in the
  brief: a shortcut never covers a guard, contract items are never reported, the concrete case is the failure.
- Reviews: B passed every claim; its fix round added the never-cut list to TRIAGE.md, made the no-new-test exception
  cover only a pure deletion, gave eng-lead a route for these findings, and added tests that installed agents match
  their roster files and that the principles' line counts match. A passed five of six (a Go example's claim was
  false); its fix round fixed it, added a regression test rule for bug fixes, a public-interface caveat for deletions,
  a size limit, escaped output and safer path handling in `debt.mjs`, and two ruleset lines (below).
- The measurement ran on the branch before the merge, as planned.

## Results

- Measurement (`skill-eval`, 2026-11-16, `claude-haiku-5-5`, three tasks: a CSV export, a date field, a midnight
  bug in a shared function; three runs each without and with the ruleset in the prompt, judged blind; 0.10 US dollars):
  judge totals out of 25, plain to rules, 21 to 22, 23 to 24.7, 21 to 21.3; a blind reader 22 to 23.3, 22.7 to 24.7,
  23.7 to 24.3. The ruleset runs changed +2 lines on the bug fix against +9 to +12, but two of three left out a summer
  time test. So the hook stays on by default, and the ruleset's test line now asks for "a small test of the edge cases
  they turn on" for non-trivial logic and every bug fix. It also ends with "The project's instructions and the task's
  output format come first". Small sample, one small model; not proof for other models.
- 1 new skill (39), 1 new hook (15). The ruleset is 1,400 characters, the hook's context 1,532.
- Left as they are, for the owner: a `shortcut:` marker inside a string, heredoc or triple-quoted string that holds a
  comment opener is counted; UTF-16 files are skipped; builders get the ladder twice (from the hook and from their own
  agent file); `tests/lazy-senior-debt.test.mjs` is near the 20,000-byte limit.
