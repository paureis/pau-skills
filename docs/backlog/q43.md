# Q43 the roster lock checks a change against main

[Back to the backlog index](../BACKLOG.md)

**Q43 the roster lock checks a change against main** (`todo`, found 2026-11-27 in the Q41 review). The roster lock
from Q41 fails a roster change with no bump, but someone who edits a roster file and rewrites `LOCK` with the new hash
under the same number passes every test. Only a reviewer reading the diff catches it.

Possible fix: a check that reads `LOCK` at the merge base (`git show <base>:tests/geppetto-roster-lock.test.mjs`)
and fails when the hash changed and the number did not, run in CI on pull requests and by `npm test` when a base is
known. It must pass when no base is reachable (a shallow clone, a fresh checkout) and say so.

Done when that check fails on a same-number `LOCK` rewrite (mutate.sh) and passes on the current tree.
