# Q29 friction-review: what slows the agent down, across sessions

[Back to the backlog index](../BACKLOG.md)

**Q29 friction-review** (`todo`, decision 31, after Q28). The owner wants a review loop: look at the last 30
sessions, find what could be streamlined, make those changes, and repeat after the next 30. Upstream `retro`
(mattpocock/skills `skills/engineering/retro/SKILL.md` at abeeaf9, MIT, read 2026-11-24) is the method, but it reads
one session (the current one by default), names no path and has no script.

## What upstream `retro` does

It reads the session, sorts friction into seven kinds, each with a "use when": navigation (add a pointer), automated
checks ("A repo with no guardrail ... is itself a finding"; a mechanical standard "gets a deterministic check"),
coding standards (judgement calls go to the reviewer), a global instructions file that is too large, tool economy
(costly or token-inefficient tool calls), no-ops in steering files, and information access (logs, read-only access to
services). It presents candidates by severity and changes nothing until the user picks one. It is "not a memory
system". Upstream's unfinished `chief-of-staff` runs it on about one in five subagent sessions, failures first.

## How ours differs

- It reads this project's last 30 sessions (`~/.claude/projects/<folder>/*.jsonl`, the count an option) and counts
  each friction kind across them, so a candidate is something that repeats; one session on request.
- It reuses what we have: copies of `agent-friendly-audit`'s `mine-transcripts.mjs` (folder finding, redaction of
  emails, secrets and the home folder) and `skill-eval`'s `extractActions` (a transcript reduced to tool actions),
  under `tests/standalone.test.mjs`'s COPIES rule.
- Upstream's `CODING_STANDARDS.md` and reviewer agent become our per-folder `REVIEW.md`, the roster `reviewer` and
  `review-triage`. Examples cover Make, pyproject, Cargo and Go as well as package.json. `writing-for-agents` is
  optional.
- Typed only (decision 31), on the confirm list if it starts subagents. Overlaps to keep apart: `retrospective` (the
  user's corrections in one session), `agent-friendly-audit` (mistakes that happened twice, from the user's words and
  fix commits) and `instructions-audit` (the instruction files themselves).
