# Q18 tests for the description rules checked by hand

[Back to the backlog index](../BACKLOG.md)

**Q18 tests for the description rules checked by hand** (`in progress`, scope settled in decision 20). In Q17 the plan
check of the rewording brief broke each description rule once on purpose and found four that pass every test. The
builder checked them by hand (`docs/backlog/things-that-bit/batch-14.md`). Q18 turns them into tests, so the next
change to a description cannot break them unseen. It changes no skill and needs no paid run.

## What to test

For every `SKILL.md` description in `skills/`:
1. No curly quote or apostrophe: none of U+2018, U+2019, U+201C or U+201D. A curly-quoted phrase slips past the
   request-1 check and the copied-wording check in `tests/trigger-lists.test.mjs`, which read only the ASCII
   apostrophe.
2. No backtick at all. Today `tests/standalone.test.mjs` catches a backticked skill name only when the paragraph does
   not say "if installed" or "is installed", and a description is never a place for code.
3. Exactly one "Use ..." opener (`Use when`, `Use whenever`, `Use before`, `Use for` or `Use after`, as
   `tests/trigger-lists.test.mjs` reads it). A second opener placed earlier would become the one the request-1 check
   reads.
4. On a skill in `CONFIRM_LIST` (`tests/confirm-step.test.mjs`), no quoted phrase ends with a question mark: a
   question is written as a situation ("Policy since P0.5" in `docs/backlog/context-budget.md`). A quoted remark is
   not something a test can tell from a request; that part stays a review rule.

On 2026-11-04 (main at aa085ec) all 38 descriptions pass all four, so each test is a guard: it passes at the base and
must be proven with `mutate.sh` on a copy of a description that breaks it.

## Changed in the orchestrator's review before the build (2026-11-04), and why

Checked against the code at 68bf91e (main, aa085ec plus the decision 20 pull request). All 38 descriptions are still
plain ASCII, none holds a backtick or a question mark, and each has exactly one "Use ..." opener (13,592 characters
in all), so each test is still a guard.
- **Rule 1 covers every quote-like character, not four.** A low-9 or reversed quote, a guillemet or a prime slips past
  the same checks as a curly one. The test flags any character of Unicode's Quotation_Mark set other than the ASCII
  apostrophe and double quote, and the look-alikes U+00B4 (acute accent), U+02BC (modifier letter apostrophe) and
  U+2032 (prime).
- **Rule 4 covers a question mark anywhere in a quoted phrase, or right after its closing quote.** "Ends with" misses
  a phrase with the question mark outside the quote, or in the middle. A question mark elsewhere in the description is
  allowed, and a skill off the confirm list may quote a question.
- **One place still decides the confirm list.** The new test needs `CONFIRM_LIST`, and a test file cannot be imported
  without running its tests twice, so the list moves to a plain module, `tests/confirm-list.mjs`, that both tests
  import. `docs/ADDING-A-SKILL.md` and "Policy since P0.5" name the new file.
- **Descriptions are read the way `tests/trigger-lists.test.mjs` reads them**: one double-quoted frontmatter line with
  no backslash or double quote inside. A description the test cannot read is a failure that names the skill, never a
  skip, so an escaped curly quote cannot hide.
- **Each check also runs on fixtures both ways**: a case it must catch, and a near case it must pass (a straight
  apostrophe, "Use it when", a question mark outside any quote on a confirm-list skill, a quoted question on a skill
  off the list).
- **Each proof fails only its own rule.** Every mutation runs the new test file alone, and its output must show that
  the failing test is the one for that rule, so a mutation caught for another reason (a description that no longer
  reads) does not count.
