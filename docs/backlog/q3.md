**Q3 designer agent** (`done`, eighth batch, [pull request 41](https://github.com/paureis/pau-skills/pull/41), agent-orchestration: a designer template in `geppetto`). Asked for by the owner on 2026-10-19, left out of Q2's first roster.
- Origin: Peng Zheng's design bot in the same episode. It edits Figma through the Figma MCP and uses a skill that
  knows his files and design system; he designs the system and one keyframe ("I will do the first 5%") and the bot
  extends it into every screen of the flow.
- What it does: a `designer` agent that `geppetto` creates on request, at project scope so it can carry `mcpServers`
  (plugin agents cannot), with a short design-system skill or file it reads first (tokens, type, spacing, how the
  files are laid out). It extends a keyframe into further screens using only the system's tokens and reports any
  value it had to invent.
- Blocked on: a working Figma connector. In the 2026-10-19 session the Figma MCP failed to connect (proxy 403). Without
  Figma, the same agent can work on a code design system (a tokens file and components).
- Done when: on a fixture design system with one keyframe, the agent produces a second screen that uses only system
  tokens, flags anything it invented, and passes `geppetto`'s audit.
- Changed in the eighth batch's review (2026-10-23), and why:
  - The Figma connector failed a third time (the design plugin's Figma server was refused by the proxy with a 403,
    and no Figma tool loaded), so the designer works on a design system in code. Create adds a design MCP server
    (`mcpServers` and `mcp__<prefix>__*` in `tools`, the prefix read from the session's tool list) only when the user
    names one that already works; the audit accepts that form, and the path stays unproven until a session with a
    working connector runs it. With a `tools` list an agent gets no MCP tool unless it is listed (sub-agents docs).
  - The designer is a template, `templates/designer.md`, outside `roster/`: Create uses it on request and Install
    never copies it.
  - The design-system notes are a section of the agent's own body, filled at Create time with paths and token names,
    never values, so nothing else is installed and the values cannot go stale. The agent re-reads the tokens file on
    every run.
  - Tools Read, Glob, Grep, Edit and Write, no Bash, no memory, no production rules block (it writes no server code).
    Its report has an "Invented values" field and, after the build, a "Literal search" field with the patterns and
    hits as evidence.
- Changed during the build (plan check, review and cold run), and why:
  - The plan check's own cold run showed `font-weight: bold` and `border: thin` going unlisted, so the fixture's
    tokens gained weight, leading and border width, and the literal search lists unitless numbers and keywords.
  - The review found the search was a closed list (`oklch(`, `60ch`, `opacity: 0.95` and `width="20"` passed), and
    that Update would take the template as the bundled copy of a designer and merge its placeholders back over the
    project's design system. The search is now a floor that names every colour function, unit and keyword family,
    and Update replaces only the covenant and rules blocks of an agent Create made. Update also keeps the `skills:`
    line Install added, which a three-way merge drops without a conflict.
  - Create reads its bundled files before the first question: in a headless `--resume` turn the skill's read grant
    was gone.
  - Cold run (claude-opus-5-5, empty HOME): Create asked six questions, showed the file and wrote it on a yes; the
    audit and `claude plugin validate` were clean; the designer wrote `screens/order-confirmed.html` from the
    components and tokens and listed its one invented value, the success colour, which an independent scan confirmed
    as the only literal. Left as found: Create's step 4 scratch folder outside the project is refused in a headless
    acceptEdits run (older than this item).
