# Q19 descriptions in printable ASCII only

[Back to the backlog index](../BACKLOG.md)

**Q19 descriptions in printable ASCII only** (`done`, fifteenth batch, [pull request 67](https://github.com/paureis/pau-skills/pull/67); scope settled in decision 21). The Q18 review found that
the description rules let through a fullwidth question mark (U+FF1F) inside a quoted phrase on a confirm-list skill,
and quote ornaments such as U+275B to U+275E. Rule 1 named a set of quote marks; Q19 turns it into "every character of
a description is printable ASCII" (U+0020 to U+007E), which closes both gaps. It changes no skill and needs no paid
run.

## What to change

- Rule 1 in `tests/description-rules.test.mjs` flags every character outside U+0020 to U+007E, named as `U+XXXX` (at
  most one problem per skill, as now). The Quotation_Mark set and the three look-alikes are no longer needed.
- Rule 4 stays as it is: with rule 1, a question mark other than the ASCII one cannot reach a description.
- The fixtures: every former rule 1 case still fails; the cases that passed on purpose (U+00E9, U+00B7, U+2033) now
  fail; U+FF1F, U+275B, a tab and U+007F fail; the space, the tilde, the straight apostrophe and the double quote pass.
- `docs/ADDING-A-SKILL.md` step 2 and "Policy since P0.5" say "printable ASCII only" (the orchestrator's files).

## Done when

- A proof on a real description with U+FF1F in a quoted phrase on a confirm-list skill is CAUGHT by rule 1, and the
  Q18 proof M1 (curly quotes) still is; mutations of the new range (each end moved by one) are CAUGHT; every run
  reports its `# tests` line.
- The four repository checks pass.

## Changed during the build (plan check, review and fix round), and why

- `eng-lead` planned one slice: the new check, test 7 rewritten with a sweep of U+0000 to U+00FF at the start, the
  middle and the end of a description, three proofs on real descriptions (U+FF1F on arena and quote ornaments on
  grill-me, which both SURVIVED at the base, and the Q18 curly quote proof on tdd), and 23 mutations of the range and
  the message.
- The plan check built the slice in a clone (every done-when passed) and found eight mutations the planned fixtures
  missed: a hard-coded skill id, only the first skill checked, only the first 100 characters read, and four ranges let
  through (U+200B, U+2000 to U+2017, U+FEFF and U+2028, astral characters). The sweep went to U+FFFF, and a long
  description and a two-skill case were added.
- The review passed every claim; an oracle compared rule 1 with a hand decoder on every code point and 20,000 random
  calls with no mismatch. Its mutations found that rule 1 could check only the last skill and every test would stay
  green, because the brief's two-skill case put its bad skill last; so test 2 would have missed a U+FF1F on 37 of the
  38 skills. One fix round added cases with the bad skill first and in the middle, four bad characters, more astral
  points, tag characters, and a reader case that keeps a leading tab and the spaces at both ends.
- `tests/description-rules.test.mjs` ends at 19,811 bytes, 189 under the size limit: the next change to it needs room
  first.

## Results

- Rule 1 flags every character outside U+0020 to U+007E. 11 tests in the file and 1,500 in the suite, as before. The
  three proofs were CAUGHT by test 2 alone after the change; 31 planned mutations and the review's 6 were all CAUGHT,
  each by the test the brief named. Test 7 takes about 0.9 seconds.
