# Q28 some skills typed only again

[Back to the backlog index](../BACKLOG.md)

**Q28 some skills typed only again** (`todo`, decision 31). Upstream mattpocock/skills (abeeaf9, read 2026-11-24)
splits skills into user-invoked ("reachable only when you type them ... their job is to orchestrate") and
model-invoked, with `disable-model-invocation: true`, and a router for the user-invoked ones. Its rule: "could the
model usefully reach for this autonomously?" and "If it only ever fires by hand, make it user-invoked and pay no
context load." A user-invoked skill may start model-invoked ones, never another user-invoked one.

## First step

The owner installs skills by uploading zips to claude.ai. Nobody has checked that claude.ai and the synced copies
under `~/.claude/skills/synced/` honour `disable-model-invocation`, or that a typed `/name` still starts such a skill.
Before the split, upload one skill with the flag and check both, in the terminal and the desktop app. Also run
`which-skill`'s `usage-report.mjs --days 90` on the owner's machine: a skill the agent never started is a safe move.

## The proposed split (from the research, to settle in the plan)

Typed only (14): `session-close`, `handoff`, `retrospective`, `lean-subagent-dev`, `methodology`, `overnight-run`,
`skill-eval`, `hillclimb`, `agent-friendly-audit`, `instructions-audit`, `geppetto`, `launch-readiness`, `to-prd`,
`to-issues`. The other 25 stay model-invoked, each because another skill starts it, the agent should reach for it from
the situation, or a newcomer must reach it without knowing names (`which-skill`, `project-setup`). Check the full
start map again (a grep for "use, run, start or offer" missed phrasings such as "if it is installed").

## What the owner's checks showed (2026-11-24)

- The claude.ai test passed in the desktop app: `/typed-only-test` (uploaded with `disable-model-invocation: true`)
  ran when typed, and a plain request to run it got "Couldn't load skill" and a pointer to type
  `/anthropic-skills:typed-only-test`.
- The usage log covers 30 Oct to 24 Nov 2026 (about 25 days, 476 starts, most for the owner's own skills outside this
  repository). This repository's skills: `session-close` 33, `safe-merge` 26, `lean-subagent-dev` 17,
  `parallel-worktrees` 16, `handoff` 6, `grill-me` 4, `brainstorm` 2, `architect`, `to-prd`, `launch-readiness` and
  `retrospective` 1 each. Never started: `tdd`, `evaluator`, `mutation-test`, `bug-fix`, `review-triage`,
  `verify-app` and `lazy-senior`, among others.
- Almost every start was logged as `agent`; the only `typed` start was `which-skill`. So the log cannot be trusted to
  tell a typed start from the agent's (Q32). Read the counts as starts, not as who started them.
- What it means for the split: the three most used typed-only candidates are already on the list; `safe-merge` and
  `parallel-worktrees` stay model-invoked because other skills and the merge guard send the agent to them; the
  verification skills that never started stay model-invoked, since typed only would hide them from the agent for
  good. Why they never start is a trigger question for a later item, not for this one.
