# Q16 trigger tests and a skill usage log

[Back to the backlog index](../BACKLOG.md)

**Q16 trigger tests and a skill usage log** (`todo`, scope settled in decision 18). The owner asked for a new
capability and, a month on, two things: proof that the skills change what an agent does, and fewer misfires (the
right skill starts for the right request, and a wrong one does not). A brainstorm on 2026-10-26 weighed eleven
options; the owner chose these two together, and an interview settled the rest.

Two facts from the brainstorm, each from a one-turn headless run in an empty folder (8 US cents each):
- A run with `-p "<request>" --max-turns 1 --output-format stream-json --verbose` shows the skill the agent starts
  as a `Skill` tool call (`{"skill":"<plugin>:<name>"}`), then ends with `error_max_turns`.
- A `PreToolUse` hook with matcher `Skill` receives `tool_name: "Skill"` and `tool_input.skill`. A typed `/name`
  does not go through the Skill tool: it reaches only `UserPromptSubmit`, as the prompt text.

## Part 1: a trigger mode in skill-eval

- A new command in `skill-eval`, for anyone's skills: given a folder of skills, a folder of request lists, a model,
  a number of repeats and a cost cap, it runs each request as a one-turn headless `claude -p` and records the first
  skill started, or "none". It reports per skill: hits (a request that should start it did), misses, and misfires (a
  request that started another skill), and flags each request whose repeats disagree.
- Each run uses an empty HOME, only the project's settings and no MCP server, the way `skill-eval run` does, and sees
  only the skills under test; an `--also <folder>` flag adds other skills to test against.
- It prints its estimate before the first run and stops before it passes the cap. A summary goes to a file; given the
  previous summary, it prints what got better or worse.
- `skill-eval`'s SKILL.md is 17,043 bytes, so the mode goes in a new script and a new reference file next to it, with
  a short section in SKILL.md. `skill-eval` is already on the confirm list.

## Part 2: this repository's request lists and the first baseline

- `evals/triggers/<skill>.json`, one per skill, outside the skill folders, so the zips do not change. Each holds 3
  requests that should start the skill (one phrase from its description, one paraphrase that is not in it, one
  situation in plain words) and 2 near misses, each naming the skill, or "none", that should start instead.
- An agent that never sees the descriptions writes the paraphrases and situations, from each skill's body and the
  README's problem lists, so it cannot copy their wording. The orchestrator checks every list before the paid round.
- `npm test` checks the lists' shape: one per skill, 3 and 2 requests, every named skill exists. CI has no model, so
  the paid run is never part of it.
- The first full round: 38 skills, 190 requests, 2 repeats, 380 runs, about 30 US dollars with a cap of 40, on the
  model the session runs, priced to the owner before it starts. Its summary is committed in `evals/triggers/` as the
  baseline.
- This batch measures only. Rewriting the descriptions that misfire is a follow-up item, with the numbers in hand.

## Part 3: the skill-usage hook and the report

- A new hook, `skill-usage`, in `hooks/session-discipline/`, on by default and off through the hook config or
  `PAU_SKILLS_DISABLE`, like every hook here. `PreToolUse` with matcher `Skill` records a skill the agent started;
  `UserPromptSubmit` records a typed `/name` that names a skill.
- One line per start: the time, the skill name and how it started (typed or by the agent). Never the prompt, the
  folder or the session. It writes to a file under `~/.claude/pau-skills/`, outside every repository, trims the file
  when it passes about 1 MB, and exits 0 on anything it does not understand.
- `which-skill` gets a report script in its own folder: starts per skill, typed and by the agent, and the skills that
  never started in the last 30 days, for "which skills do I actually use?". Without the log it says how to switch
  the hook on. It works on its own, with only the skill uploaded.

## Done when

- Each part is built test first, its tests are proven with `mutate.sh`, and the four repository checks pass.
- The first round ran within its cap and its baseline is committed; the pull request shows the near misses and the
  worst misfires.
- Versions: `skill-eval` (verification) and `which-skill` (session-discipline) get minor bumps, with
  `pau-skills-hooks` and the bundle. The owner gets two zips and the hook update commands, and the profile README
  says 14 hooks.
