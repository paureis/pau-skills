# Q42 the watchdog reads agent folders the way Claude Code does

[Back to the backlog index](../BACKLOG.md)

**Q42 the watchdog's agent folder reading** (`done` 2026-11-27, pull request 106, release v0.27.2; found 2026-11-27 in the Q39 review and cold run). After Q39 the
read-only rule in `hooks/agent-orchestration/subagent-watchdog-agents.mjs` skips files with no frontmatter. Three
differences from Claude Code 2.1.332 remain, all on the cautious side (an agent counts as one that edits):
- Claude Code loads a file whose frontmatter its parser accepts but ours does not, such as an unclosed flow list
  `tools: [Read, Grep`. Ours calls it a parse failure, so every agent read after it is not read-only.
- Claude Code reads subfolders and follows links (it lists `*.md` with ripgrep `--follow`); the watchdog reads one
  level.
- Claude Code drops a file with no `description`; the watchdog would still take it as the match.

Probe each first (headless, empty HOME, the init event's agents list), then decide case by case whether matching it is
worth the code. Done when each change has a test that fails without it.

Built in the twenty-seventh batch. Four probe rounds (2.1.332, headless, empty HOME, the init agents list) settled
every case: an unclosed list loads and its first entry names no tool; subfolders, links, hidden and git-ignored
entries load; no description, or one that is empty (`""`, `''`, `~`, `null`, a comment, an empty block scalar), is
dropped; `.MD` is not loaded; a `.md` inside `.git` loads. All three changes were worth the code. The walk is breadth
first with limits (200 files, 200 folders, depth 8, 5,000 entries), and a type defined twice is read-only only when
every definition is. Two choices differ from Claude Code on purpose: `.git` folders are skipped (a git history passed
the folder limit), and broken links are skipped rather than unknown. The cold run matched 9 of 9 agent types.
