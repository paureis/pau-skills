# Q39 what Q38 left: the newest snapshot of the session, and stray files in an agents folder

**Q39 what Q38 left** (`todo`, found in the twenty-fourth batch, 2026-11-26). Two small gaps the Q38 reviews and the
release notes named. Neither breaks a session.

## 1. compact-snapshot shows no snapshot when another session wrote a newer one

`compactNote` reads only the newest snapshot in the folder. When that one belongs to another session (two sessions in
one project), the note shows no snapshot text at all, though an older snapshot of this session is there. Fix: pick the
newest snapshot whose `session:` line matches, and fall back to none. Test: two sessions' snapshots, the other one
newer; the note shows this session's.

## 2. A stray `.md` file in an agents folder turns off the read-only rule

`definedReadOnly` in `hooks/agent-orchestration/subagent-watchdog-agents.mjs` answers "not read-only" when any `.md`
file before the match cannot be read or parsed, because that file might be the type's own definition. A README or
notes file with no frontmatter therefore makes every agent read after it count as one that edits. That is the safe
side, but it is noisy. Possible fix: a file with no frontmatter at all cannot be a definition, so skip it; keep the
rule for a file that has frontmatter and fails to parse, or is over the size cap. Settle it with a probe: does Claude
Code load an agent from a file with no frontmatter?

Done when both have tests that fail without the change (mutate.sh), and the release notes' known issues drop them.
