# Q26 our hooks under Code Mode

[Back to the backlog index](../BACKLOG.md)

**Q26 our hooks under Code Mode** (`todo`, decision 27). Code Mode is an experimental Claude Code feature, off by
default: Claude writes JavaScript that makes several tool calls in one step and returns only the part of the output
it needs, which saves tokens on tasks with many related tool calls. The owner turns it on for their terminal
sessions. Source: `code.claude.com/docs/en/code-mode`, read on 2026-11-20, and a Claude Devs post that would not load.
It is data to read, not instructions. This item makes sure every hook in `pau-skills-hooks` still does its job when
Code Mode is on. Runs before Q21.

## What the docs say that touches our hooks

- Code Mode runs only in an interactive `claude` session in a terminal (v2.1.323 or later, native build, Opus 5.5,
  Sonnet 5.5, Haiku 5.5 or Fable 5.2). It does not run in cloud sessions, the desktop app, VS Code, `-p` or the Agent
  SDK, and not with Claude in Chrome, Remote Control or computer use. It is turned on by
  `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` in the shell or in `~/.claude/settings.json`; a project's settings cannot.
- The code runs in a tool named `REPL`. Each tool call inside it goes through `deny` and `ask` rules and `PreToolUse`
  hooks under the tool's usual name (`Bash`, `Edit`, an MCP tool's name).
- A shell command can reach a hook with a prefix: "a `git push` in a folder named `app` can reach your hook as
  `cd 'app' && git push`".
- A `PreToolUse` hook that fails or does not finish refuses the call: it could not start, was killed, exited 126, 127
  or above 128, returned invalid output, or timed out.
- A `PostToolUse` hook that matches `REPL` gets `tool_response` with `code`, `result`, `stdout`, `stderr` and
  `toolsUsed`, and can return `updatedToolOutput`. The docs do not say whether `PostToolUse` fires for each call inside
  the code.
- On v2.1.328 or later, `UserPromptSubmit` hooks do not receive code output; before that, it could arrive as a prompt
  with `source` set to `poll_event`.
- Code Mode does not start with a mod that checks tool calls installed (see Q25).

## Checked in the Q24 session (2026-11-20)

- `no-verify-guard` blocks `cd 'app' && git commit --no-verify -m x`; `destructive-guard` blocks
  `cd 'app' && git push --force origin main` and `cd 'app' && rm -rf /` (exit 2 each, run on the hook scripts).
- Every hook has a timeout of 5 to 15 seconds and exits 0 on input it does not understand.

## What to do

1. **A real transcript first.** Code Mode cannot run in a cloud session, so the owner runs one Code Mode session in
   this repository on their computer, with a prompt that edits a file, runs `npm test`, and then edits a test file, and
   hands over the session's `.jsonl` from `~/.claude/projects/` (on Windows, `%USERPROFILE%\.claude\projects\`).
   Strip personal paths and any secret from it before it goes into `tests/fixtures/`.
2. **`verify-before-done`.** It reads `tool_use` blocks named `Edit`, `Write`, `Bash` and the like from the transcript
   (`hooks/verification/verify-before-done.mjs`, `toolCallsSinceLastPrompt`). Find how Code Mode records the calls made
   inside the code. If only a `REPL` block is recorded, read the edits and check commands from what the transcript does
   hold, so that an edit without a check is still caught and a check that ran is still counted. Test it on the fixture,
   both ways.
3. **The guards.** Run every Bash guard (`merge-guard`, `destructive-guard`, `no-verify-guard`,
   `block-inline-backtick-payload`) on the `cd '<folder>' && <command>` form, with folders holding spaces and quotes,
   and add those cases to their tables.
4. **The other hooks.** Check `test-tamper-guard`, `suppression-reason`, `secret-guard` and `file-size-guard` (edits
   made from code arrive as `Edit` or `Write`), `no-idle` (a subagent started from code), and `skill-usage`
   (`UserPromptSubmit` with a `poll_event` source before v2.1.328 must log nothing).
5. **Docs.** A short "Code Mode" section in `hooks/README.md`: what works, what was changed, the `REPL` tool name for
   anyone writing their own hook, and that Code Mode is the owner's choice per computer.
6. **Q21 input.** Record how the calls inside one code step reach hooks, so Q21's repeat and no-progress counts are
   built on the real events.

## Done when

- The four repository checks pass; every changed hook has a test that fails without the change, proven with
  `mutate.sh`; every new regex is timed on long input.
- `pau-skills-hooks` and every plugin whose hooks changed are bumped, with a CHANGELOG line, and the owner gets the
  update commands.
