# Q22 two hooks that get in the way

**Q22 two hooks that get in the way** (`todo`, decision 24). The owner hit both in a Windows 11 desktop session with
`pau-skills-hooks` 0.4.1 (main f89e626). Fix both in `pau-skills-hooks` 0.4.2, with tests, and leave the work for
the owner's review: commit on a branch, do not push until the owner says so. Keep every example generic: the project
where this was seen is private and is never named or described.

## 1. verify-before-done misses check scripts (the main annoyance)

File: `hooks/verification/verify-before-done.mjs` (Stop hook).

Symptom: in a project whose only check is a shell script, every turn that edits a code file is sent back once with
"no test, build, lint or type check ran after the last edit", even when the full check ran after the last edit and
passed. The agent then reruns a check of one or two minutes, or writes a paragraph saying it already did.

Cause, confirmed on main 504d344: `VERIFY` matches none of these real commands:

```
bash tools/check.sh --quiet
bash tools/check.sh --quiet </dev/null; echo EXIT=$?
timeout 600 bash tools/check.sh --quiet </dev/null > out.txt 2>&1
lune run tests/run
```

The workaround, `testCommands` in `.claude/pau-skills.json`, exists, but the project had no such file and nothing
pointed to it, so the hook only blocked.

What to change, in order of value:
1. **Read the checks the project already declares.** `lean-subagent-dev` (and `review-triage`) read `checks` from
   `.claude/review-rules.json`, for example `"checks": ["bash tools/check.sh --quiet"]`. When that file lists checks,
   a shell command that contains one of them counts as verification. One source of truth, no second config to forget.
2. **Recognise common check-script shapes**: `bash`, `sh`, `pwsh`, `powershell`, `node` or `python` (or `./`)
   followed by a path whose file name contains `check`, `test`, `verify`, `lint` or `ci` (`tools/check.sh`,
   `scripts/test.ps1`, `./scripts/verify.mjs`), plus `lune run <tests path>`, `luau-lsp analyze`, `selene` and
   `stylua --check`. Anchor them to the start of a command or after `;`, `&&`, `||`, `|` or `timeout N`, so
   `cat tools/check.sh` and `grep check` do not count.
3. **Make the block message say how to stop a false alarm**: name `testCommands` in `.claude/pau-skills.json` and
   `checks` in `.claude/review-rules.json`, with a one-line example.

Also check (unverified):
- Whether task notifications and subagent hand-backs, which arrive as `user` entries with text, are read by
  `isUserPrompt` as "the user's last message". If they are, they move the window, and edits before them are judged
  against the wrong range.
- Whether a check started with `run_in_background: true` counts (it should: the command is in the transcript).

## 2. no-idle's PreToolUse rewrite fails in auto mode

File: `hooks/agent-orchestration/no-idle.mjs` (PreToolUse on `Agent|Task`, and SubagentStart).

Symptom (2026-11-11, auto mode): an Agent launch was refused with "The server-side auto mode classifier gave no
verdict for Agent: a hook changed this call's input after auto mode reviewed it." The harness then asks the agent to
send the call again with the hook's changed input, word for word: a round trip on every launch whose prompt lacks the
block. Once the block is in the prompt, the hook stays silent and the launch goes through.

Cause: the PreToolUse path returns `updatedInput` (the whole tool input with the prompt changed). Auto mode reviewed
the original input and will not approve one it did not review.

What to change:
1. **Make SubagentStart `additionalContext` the default path.** First prove that it fires for Agent-tool subagents in
   the foreground, with `run_in_background`, with `isolation: "worktree"`, and for forks, and record the evidence in
   the hook's header. (Q21's prototype on 2026-11-06 saw SubagentStart fire for a foreground general-purpose subagent
   in a headless run.)
2. **Keep the PreToolUse rewrite behind an option**, off by default (for example
   `{"no-idle": {"rewritePrompt": true}}`), for setups where SubagentStart is missing; or skip the rewrite when the
   hook input says auto mode is on (check `permission_mode`).
3. If SubagentStart turns out not to reach some agents, say so in `hooks/README.md` rather than keep a path that
   breaks auto mode.

## Review before the build (orchestrator, 2026-11-11)

Checked against main 26f5934 and this session's own transcript (Claude Code 2.1.322). Changes to the plan above:

- **`checks` from `.claude/review-rules.json`** match in the same anchored way as the script shapes (at the start of
  a command or after a separator), with spaces collapsed, not as a bare substring: `echo "bash tools/check.sh"`
  must not count. Entries that are not strings, or are empty or blank, are skipped (an empty string is inside every
  command). A missing or broken file counts as no checks; a leading byte order mark is stripped before
  parsing, as `hooks/lib/config.mjs` does. The hook reads the file
  itself rather than through `hooks/lib`, so the change bumps only the verification plugin, the bundle and
  `pau-skills-hooks`.
- **Script shapes.** A word in the file name counts only at the start of the name or after a character that is not a
  letter, and `ci` only as a whole word, so `latest.py`, `special.sh`, `decide.mjs` and `contest.sh` do not count.
  Interpreter flags before the path count (`bash -e`, `python -u`, `python3`, `pwsh -NoProfile -File`,
  `powershell -ExecutionPolicy Bypass -File`). The owner works on Windows, so `.\scripts\test.ps1`,
  `& .\scripts\check.ps1` and backslash paths count too. Separators also include a new line and `(`; `timeout` may
  carry options (`timeout -k 5 600`, `timeout 10m`). Every new pattern is timed on long input that does not match, in
  a child process with a kill timeout.
- **Tests that "fail on 0.4.1".** A "does not count" case already passes on 0.4.1, so it cannot fail there. Every
  "counts" case and every no-idle default case fails on 0.4.1; the "does not count" cases are proven by mutation.
- **no-idle.** With `rewritePrompt` on, the rewrite is still skipped when `permission_mode` is `auto`, the one mode
  where it is known to break. The option is read with `hookOptions`. `hooks.json` keeps the PreToolUse entry, so the
  option can work.
- **Layout.** Two slices with no file in common: verify-before-done with a new
  `tests/verify-before-done-scripts.test.mjs` (the existing test files stay as they are), and no-idle with
  `tests/no-idle.test.mjs`. `hooks/README.md` is the orchestrator's: both slices change it.

The two "also check" points, from this session's transcript:
- **Task notifications and subagent hand-backs.** When one arrives during a turn, the transcript stores it as
  `queue-operation` entries and an `attachment` of type `queued_command`, never as a `user` entry, so `isUserPrompt`
  ignores it and the window does not move. The user's own message carries `origin: {"kind": "human"}`.
  A Stop hook's feedback that sends the agent back is a `user` entry with `isMeta: true`, which `isUserPrompt` skips
  as well.
- **A check started with `run_in_background: true`** counts already: the call is an ordinary `tool_use` with a
  `command`. A test pins it.
- **A notification that arrives while the session is idle** starts a new turn, and the transcript stores it as a
  `user` entry with text content, `origin: {"kind": "task-notification"}`, `promptSource: "system"` and
  `turnOrigin: "task_notification"`. `isUserPrompt` returns true for it (checked with the hook's own function), so
  it does move the window: edits made before it are no longer seen. The fix reads a `user` entry whose `origin.kind`
  is present and is not `human` as not the user's message. An entry with no `origin` (older transcripts) keeps
  today's rule.

Where SubagentStart fires, from two headless runs on 2026-11-11 (Claude Code 2.1.322, Haiku, 0.05 US dollars in
all, approved by the owner), with a hook that logged each event and returned `additionalContext`:
- SubagentStart fired for an Agent launch in the foreground, with `run_in_background: true`, with
  `isolation: "worktree"` (its `cwd` is the agent's worktree), and for `subagent_type: "fork"`. Each subagent's own
  transcript holds a `hook_additional_context` attachment with the hook's text. The subagents' own answers to "do
  you see the line" disagreed with their transcripts, so the transcripts are the evidence.
- PreToolUse input for Agent carries `permission_mode` (`acceptEdits`, `auto`); SubagentStart input does not.
- In headless auto mode, no-idle 0.4.1's rewrite was accepted by the classifier and the launch went through, so the
  owner's refusal (desktop app) was not reproduced headless. The fix stands: SubagentStart reaches every kind of
  launch, so the rewrite is not needed by default.

Settled by the orchestrator after eng-lead's plan (the owner can reverse any of them at review):
- A word in a script's file name also starts at a capital letter after a lowercase one, so `RunTests.ps1` and
  `runChecks.mjs` count. `zsh` and an optional `.exe` on an interpreter name count. Left out: `VAR=1`, `time`, `env`,
  `sudo`, `nohup`, `then` and `do` before a command, and `bun` or `deno` as interpreters.
- A declared check is literal text, case-sensitive, followed by the end, a space or one of `; & | ) < >`, and may
  follow a `timeout` prefix. `checks` in `.claude/pau-skills.json` does not count: the review-rules file is the one
  source.
- `rewritePrompt` is on only for the value `true`.
- One existing fixture changes: `./scripts/check-all` in `tests/verify-before-done.test.mjs` now counts by design, so
  that test uses a command no rule counts.
