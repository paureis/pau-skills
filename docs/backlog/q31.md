# Q31 patch notes for every batch

[Back to the backlog index](../BACKLOG.md)

**Q31 patch notes** (`todo`, decision 31, after Q30). The owner wants an easy changelog of what each batch changed,
with a game feel: a GitHub Release per batch, written like video game patch notes, with emojis and GIFs.

## What the plan must settle

- Where the notes live. `npm run scrub` refuses non-ASCII in tracked files, so emojis either stay on GitHub only or
  their folder (for example `docs/releases/`) gets an exemption with a test.
- How a release is made. The session's GitHub tools read releases but cannot create one; a workflow that runs
  `gh release create` with the notes file when a version tag is pushed is the likely route. Pushing a tag from a
  session may also be refused; check it.
- GIFs: a release body shows images by URL. Use images the project may use (its own, or ones whose terms allow
  linking), never a hotlink that can break or change.
- What each release says: new and changed skills and hooks, version bumps, the counts (skills, hooks, tests), what the
  owner uploads or updates, and a short "known issues".
- Backfill: one release for the batches so far, or start from the next one.
