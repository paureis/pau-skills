# Q21 a subagent watchdog

[Back to the backlog index](../BACKLOG.md)

**Q21 a subagent watchdog** (`todo`, direction settled in decision 22 after a brainstorm on 2026-11-06, design in decision 23). The idea came
from a post the owner saw and lost: hooks that check on subagents while they run, because a subagent sometimes spends
30 minutes on test runs for a one-line change, stalls, or loops. The goal: no subagent runs that long on a small task;
it is nudged or stopped within minutes, saving usage, waiting time and wrong work.

## The direction: a waste detector and an orchestrator status, sharing one state file

- **Waste detector** (PreToolUse and PostToolUse inside subagents, keyed by `agent_id`): flags the same command
  (normalized) run again with no file edit in between, and a long stretch of tool calls with no edit. First a note to
  the agent (additionalContext or a deny reason that says "report what you have"), then `ask`, which surfaces in the
  main session naming the agent; Esc denies that one call without killing it.
- **Orchestrator status** (main-session hooks, where `agent_id` is absent): one line per running subagent with its
  minutes, tool calls and repeats, and a "looks stuck" flag when it has made no tool call for a while. A stalled agent
  makes no tool calls, so its own hooks never fire: only this side can see a stall. Stopping stays with TaskStop.

## Hard limits (decision 22)

- Never cut off a healthy long run (a big test suite, a real refactor).
- Stopping an agent needs a yes, the owner's or the orchestrator's. A hook cannot kill an agent anyway; it can deny or
  ask about one tool call, or add a message.
- A hook in `pau-skills-hooks`, working with no skill installed; Node standard library only.
- It works in cloud sessions.

## Facts from the documentation (hooks and subagents pages, read 2026-11-05)

- Tool hooks fire for a subagent's tool calls, with `agent_id` and `agent_type` in the input.
- SubagentStart gets `agent_id` and `agent_type` (not the prompt); the Agent tool's PreToolUse sees the prompt, and
  `no-idle` rewrote it there until Q22 (0.4.2), which made SubagentStart its only default path. SubagentStop gets `agent_transcript_path` and can send the agent back.
- No hook event fires on a timer. Notification `idle_prompt` does not fire while a background agent runs.

## Settled before the build (decision 23)

The grilling on 2026-11-06 and one headless prototype settled every open question; decision 23 holds the answers.
What the build must still respect:
- The hook cannot tell a headless run from an interactive one (`permission_mode` reads "default" in both), so "ask"
  behaves as decision 23 says in each.
- A denied call leaves a PreToolUse with no PostToolUse: a command counts as in flight only until that agent's next
  event, so a denied call never reads as a long-running command.
- Not tested: "ask" from a background subagent in an interactive cloud session. The documentation says such a prompt
  surfaces in the main session; check it once by hand after the merge.
