## What to change

- `hooks/verification/verify-before-done.mjs`: an edit counts only when its path resolves inside the project
  (`projectDir(input)` from `hooks/lib/config.mjs`; a relative path resolves against the hook input's `cwd`). Compare
  real paths where they exist, so a symlinked project or a macOS `/var` against `/private/var` does not read as
  outside; a path that cannot be resolved counts as inside (the hook must not go quiet on input it cannot read).
- The VERIFY patterns accept package-manager flags between the tool and its script (`--prefix <dir>`, `-C <dir>`,
  `--cwd <dir>`, `--filter <x>`, `--workspace <x>`, `-w <x>`).
- A Monitor call whose `command` matches counts like a shell command.
- Tests first in `tests/verify-before-done.test.mjs`, each proven with `mutate.sh`.
- The orchestrator: this repository's `.claude/pau-skills.json` gets `testCommands` for `npm run scrub`,
  `node scripts/build-marketplace.mjs --check` and `claude plugin validate`; `hooks/README.md` says "in the project";
  versions: verification and the bundle (patch), `pau-skills-hooks` (patch); a CHANGELOG line.

- `eng-lead` planned one slice with 35 tests and 44 mutations; the orchestrator moved the path tests into a third

  near the size limit.
- The plan check built the slice in a clone (all 44 mutations caught) and corrected the red run (one more test fails),
  two mutation sets, the counts for three files, two fixtures that passed for the wrong reason (a Monitor description
  standing in for a command, a relative path that a cwd fallback kept inside), and added N4 and four mutations.
- The review passed every claim (base and head run side by side as processes, 34 fuzzed inputs) and found that the
  new flag pattern could take exponential time (23 seconds at 26 quoted flags, past the hook's 10-second timeout) and
  read `yarn --cwd "my build" add react` as a check. One fix round made a bare value unable to start with a quote,
  with a timing test run in a child process, three more "does not count" cases, two spacing cases and a guard for a
  null `where`.
- Left as they are, and named in the pull request: with no `CLAUDE_PROJECT_DIR` and a cwd in a subfolder, an edit in
  the project root reads as outside (Claude Code sets the variable); edits in a git worktree or an `--add-dir` folder
  outside the project no longer count; `pnpm -w add test-utils` reads as a check (decision 22 leaves flags without a
  value out); Windows path forms such as `/c/...` and long paths were traced, not run on Windows.
