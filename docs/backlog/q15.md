# Q15 html-plan pages that are easy on the eyes

[Back to the backlog index](../BACKLOG.md)

**Q15 html-plan pages that are easy on the eyes** (`todo`, asked for by the owner on 2026-10-25, decision 16). The
owner answered the Q13 decisions page on claude.ai and found it hard on the eyes: a very white page, faint text, and a
contents rail whose items went white on white on hover. `html-plan` is installed unmodified from upstream (Q5), so
where a change lives is part of the work.

Found by the orchestrator on 2026-10-25, each reproduced in a headless browser:
- **Dark mode paints half the page.** `htmlplan.css` follows `prefers-color-scheme` and paints only `html`
  (`html { background: var(--paper); color: var(--ink) }`). The artifact host adds its own `body` with a white
  background, so in dark mode the text turns light while the page stays white: the title, "3 files" and the contents
  rail nearly vanish, and a hovered rail item is white on white. One line fixes it:
  `body { background: var(--paper); color: var(--ink); }`. The Q13 decisions page carries it since version 2.
- **A code excerpt that starts on a blank line is numbered one line low.** `doc-code src=... lines="28-31"` on
  `evals/project-setup/run.mjs`, whose line 28 is blank, dropped the blank line and still numbered from 28, so the
  highlight and the pin sat one line off. Starting the excerpt on a line with text avoids it.
- **A decisions page opens with every claim closed**, so the reader sees a list and no exhibits. `doc-plan
  open="needs"` opens the paths to the decisions; batch pages should use it.
- **The contents rail repeats the claim list** on a page with four claims.

The work:
1. Show the owner three or four variants of one real decisions page (colour, contrast, type, spacing, the rail), in
   light and dark, as private artifacts; use `prototype` or `arena` if installed. The owner picks, and the
   iterations continue until the owner is happy.
2. Decide where the change lives, recommended first: (a) a small theme file in this repository, appended to
   `htmlplan.css` when the html-plan zip is built from the pinned upstream commit, so every use of the skill gets it
   and no large file is tracked here; (b) a theme `<style>` block that only the batch's decisions pages carry; (c) a
   fork of html-plan in this repository (its runtime is 145 KB of script and 63 KB of CSS, far past the 20,000-byte
   rule, and Q5 chose not to fork). Offering the two bug fixes upstream is a separate choice for the owner.
3. Done when: the chosen design renders without contrast or hover problems in light and dark mode inside the
   artifact host (checked with screenshots of both), the owner has said yes, and the four repository checks pass.
