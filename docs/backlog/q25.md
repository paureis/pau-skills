## What mods are

A mod is a plugin with a JavaScript or TypeScript hooks module (`hooks/hooks.json` with `"modules"`) that runs inside
Claude Code. Mods are on by default from Claude Code 2.1.287 in the terminal and 2.1.286 in the desktop app; the docs
do not call them experimental. Hooks run in the terminal, the desktop app, VS Code, `claude -p`, the Agent SDK and
cloud sessions; drawing runs only where there is an interface (not in `-p` or cloud sessions). The module has no
Node.js APIs: files, processes and the network go through permission-checked `$` calls, and each event has a 10 second
limit.

Most of a mod's interface (panes, bands, the status line, the backdrop) saves no tokens. What can change what the
model reads:
- `tool.call` can shorten or replace a tool result before Claude reads it, and it sees subagents' calls (`agentId`).
- `agent.spawn` and `turn.step` can set the model or effort of one subagent or one request.
- `prompt.section` and `prompt.attachment` can drop a section; `prompt.submit` adds context.
- `$.session.usage()` gives the context tokens, the window and the percent used.
In a managed setup (managed settings, or a Team or Enterprise login) user mods' prompt hooks do not run.

## Where it could help here, and how much

- **Shorten large tool results** (a long test log, a big diff) in `tool.call`: the one real token saving. Risk: the
  model loses the line that matters. Needs a measurement before anyone relies on it.
- **Model or effort per subagent** with `agent.spawn`: fits `lean-subagent-dev`'s effort table and `arena`. It sets
  what the skills now only ask for.
- **A context meter** that suggests `handoff` earlier: shows information, saves nothing by itself.
- **The Q21 watchdog**: `tool.call` with `agentId` and a denied call fit the waste detector, but the status line shows
  nothing in cloud sessions, and a settings hook already does most of it. Keep Q21 as a settings hook.
- **No gain**: `compact-snapshot`, `verify-before-done` (the mod Stop event cannot send the agent back), `lazy-senior`
  (the same text, just moved), `no-idle`.

## The blocker

A mod needs `.claude-plugin/plugin.json`, which CLAUDE.md forbids here because every marketplace entry is rooted at
the repository. A mod would need its own folder with its own root (a marketplace entry whose `source` is that folder),
or its own repository. `claude plugin validate` and `scripts/build-marketplace.mjs` were not tried on that layout.

## First step, when the owner picks this up

One small prototype outside the current plugin layout: a `tool.call` mod that shortens one kind of large result (test
output over N lines: keep the failures and the summary). Measure it with `skill-eval` on a few tasks, with and without
the mod: tokens used, and whether the task still succeeds. Decide from the numbers.

## Not confirmed

Whether a rewritten stored row (`session.append`) changes the next request or the prompt cache; whether the skill
listing is a section a mod can shorten; whether auto mode accepts a mod-changed Agent prompt. No token saving has been
measured.
