# Q32 skill-usage logs typed starts as the agent's

[Back to the backlog index](../BACKLOG.md)

**Q32 skill-usage: typed starts** (`done`, pull request 85, 2026-11-25; found 2026-11-24, after Q31). In the owner's usage log (25 days, 476
starts) almost every start reads `agent`, and the only `typed` one is `which-skill`, though the owner types
`/session-close` and the like. The likely causes, to check with a real transcript or a headless run first:
- A typed `/name` may reach `UserPromptSubmit` with a prompt that does not start with `/name` (expanded, or with a
  prefix such as `/anthropic-skills:name`), so the typed rule never matches, and the skill then starts through the
  Skill tool, which logs `agent`.
- Or a typed start fires both events, and the typed line is dropped because no `SKILL.md` is found for the name in
  the four folders the hook checks.

Done when a typed start logs `typed` once and an agent start logs `agent` once, in the terminal and the desktop app,
with tests built on the real hook input, and `which-skill`'s report reads both right.

## What was done

The first cause on the list was close, and the second was the one that dropped the lines. A typed start never reaches
the Skill tool. It fires `UserPromptSubmit` with the prompt as typed, then `UserPromptExpansion` with the name Claude
Code resolved. The hook read the first event and kept a line only when it found a `SKILL.md` in four folders, so a
plugin skill typed with or without its prefix and a skill whose file lives elsewhere were dropped. The hook now reads
`UserPromptExpansion` and no longer listens on `UserPromptSubmit`. Built-ins, MCP prompts and `.claude/commands`
files in the scope Claude Code names stay out. `usage-report.mjs` needed no change.

What worked:
- Headless probes before any brief (an empty HOME, a hook that logs every event, under 0.20 US dollars on Claude Code
  2.1.332 and CI's 2.1.302, in `-p` and stream-json). The real payloads became the test fixtures, and replaying the
  recorded runs through the old and the new hook gave the before and after.
- The plan check built the slice in a clone and found two planned cases that could not fail before any builder ran.

What did not:
- The batch probed only headless runs, not the terminal or the desktop app; that check was left to the owner.
- A limit the brief said the README must state still got past the builder; the review caught it.

The owner's check in the desktop app (2026-11-25, after updating `pau-skills-hooks` to 0.6.1): typing
`/session-close:session-close` wrote one line, `session-close:session-close typed`, and no `agent` line after it, so
the desktop app does not also start a typed skill through the Skill tool. A request in words ("run which-skill's usage
report") wrote one line, `which-skill:which-skill agent`. The desktop app names an uploaded skill `<name>:<name>`; the
old hook found no `SKILL.md` for that prefix and dropped the line. The report counts both spellings under the bare
name. The terminal was not checked; it takes the same path as the headless runs.
