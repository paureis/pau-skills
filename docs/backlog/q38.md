# Q38 subagent-watchdog: what one orchestrated session showed

[Back to the backlog index](../BACKLOG.md)

**Q38 subagent-watchdog fixes** (`todo`, the owner's report of 2026-11-25, after Q37; decision 34). Seen in
`pau-skills-hooks` 0.6.1 in one session that ran about 14 subagents (readers, critics, writers, a builder, an
evaluator) from a main checkout, most of them working in sibling git worktrees; the machine lost power once. Each
code claim below was checked against `hooks/agent-orchestration/subagent-watchdog-logic.mjs` on 2026-11-25.

What works and stays: the 5-minute throttle of the main-session status, a status that never blocks, and the repeat rule
(it rightly reported `wc -c <file>` run 5 times in a row by a writer looping on a size limit).

## 1. An edit outside the project root is not an edit (must fix)

`isEdit()` (lines 104-115) counts an Edit, Write, MultiEdit or NotebookEdit only on a path inside the project or the
agent's cwd. An orchestrator in `C:/Repo` sends writers to sibling worktrees (`C:/Repo-feature`, from
`git worktree add`) and to the scratchpad under the temp folder; their events carry the main checkout as project and
cwd, so none of their edits count and `sinceEdit` never resets. A writer that changed 9 files (512 insertions, 260
deletions) was reported as "160 tool calls, 160 since the last edit"; another with six new files (85 KB) as "86 tool
calls with no edit".

It is serious, not only noisy: the no-edit rule goes from a note (40 calls) to a permission ask (80, 160, ...), and
`exempt` (line 240) uses the same `isEdit`, so the ask can land on the edit itself. With the owner away, a healthy
background writer stops there for good.

Fix: count every successful edit tool call as progress whatever its path, and keep the path test only where it
matters, if anywhere. Or widen the test to every worktree of the same repository (`git worktree list --porcelain`
from the project, cached per session) and the session scratchpad or OS temp folder. The plan picks one; the first is
simpler. Tests: an Edit in a sibling worktree resets `sinceEdit`; an Edit in the scratchpad resets it; an agent with
79 out-of-project edits never gets an ask; a refused edit (no PostToolUse) still does not count.

## 2. A project's own read-only agents are flagged for not editing

`DEFAULTS.readOnlyAgents` (line 50) is `reviewer`, `Explore`, `Plan`, `claude-code-guide`, `web-fetch`,
`eng-lead`. A project's own agent types (here `lector` and `critico`, with tools `Read, Bash, Write`) are not on it,
so every reader and critic gets "N tool calls with no edit" after 40 calls, though they read for 60 to 150 calls and
write one file at the end by design. The option `readOnlyAgents` replaces the defaults instead of extending them
(line 80), so the six defaults must be repeated.

Fix: treat an agent type as read-only when its definition's `tools:` frontmatter has no Edit, MultiEdit or
NotebookEdit (a lone Write is the report file); make the option extend the defaults; name the option in the note text
so the orchestrator knows the way out. Tests: an agent type with `tools: Read, Bash, Write` is read-only; the option
adds to the defaults. Find where the hook can read the agent definition (`.claude/agents/<type>.md` in the project,
the user's agents folder, a plugin's agents) before planning, from real SubagentStart input.

## 3. An agent that died with a call in flight is never dropped

`judge()` (line 273) drops an agent only when it has no call in flight. After the power cut and a new session, two
agents that each had a call in flight stayed in the state, reported as "running Edit for 90 minutes" and growing.
They no longer exist: TaskStop answers "No task found" and SendMessage "No agent named ... is reachable", so the rule
that a main-session TaskStop removes the agent never fires either.

Fix, any one is enough: on SessionStart in the main session, drop every agent whose last event is older than the
session start; or drop a call in flight older than a hard limit (about 2 hours) with no wait; or remove the agent on a
failed TaskStop that names it (PostToolUseFailure with "No task found"). Tests: a call in flight older than the session
start is gone after SessionStart; a 3-hour flight with no wait is dropped. Take the failure text from a real run.

## 4. Small things

- "top repeat 1 runs of ..." prints for every agent (line 278); one run is not a repeat: print it only when
  `a.top.n >= 2`.
- The status header says "Subagents running now" (line 302) and lists agents that sent their final message but whose
  SubagentStop has not arrived. "Running or just finished" is truer, or skip an agent with no call in flight and no
  event for a couple of minutes.

## 5. Not verified

Whether an ask was pending for the two writers when the power went: both had a call in flight from the same minute,
one at exactly its 160th call (an ask threshold), the other on its 5th identical `wc -c` (the repeat ask). A log line
when the hook returns an ask (agent id, call number, reason), outside every repository and with no command text or
secret in it, would settle it next time.
