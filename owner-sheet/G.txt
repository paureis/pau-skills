## What it said at the end (not evidence: grade what it did and what it changed, not this)

The Europe section now shows "Desk lamp 42.00 EUR" when you run `node bin/price-list.mjs us eu`. `npm test` passes with 10 of 10, up from 9 plus the new test.

**Root cause:** `priceFor` in `src/prices.mjs` cached each price under the product code alone, so the region wasn't part of the key. In a two-region run, the first region's entry (US) was stored under `lamp`. The EU lookup then hit that entry and returned 39.00 USD. A single-region run only ever filled the cache for that region, which is why `eu` on its own looked right.

**Fix:** the cache key is now `${regionCode}:${code}` (`src/prices.mjs:15`). I did not change the read-once behaviour. The existing test that checks a price is read from the catalog only once still passes.

**Proof:**
- Before the fix, the bug reproduced on every run I made.
- I added a regression test and committed it on its own as `da6f67f`. It failed for the reported reason, then passed after the fix in `a92a56d`. Both commits are on the branch `fix-region-price-cache`.
- After the fix, two runs of `us eu` both print 39.00 USD for the US and 42.00 EUR for Europe.
- I did not undo the fix to watch the new test fail a second time. Its red run at `da6f67f` is the evidence.

**Safe because:** the change only makes cache keys more specific. The only other caller I saw is `src/cart.mjs`, and I did not read that file. The full suite passes, which is the strongest check I ran on it.
