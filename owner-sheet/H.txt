## What it said at the end (not evidence: grade what it did and what it changed, not this)

The first renewal for a 2025-01-31 monthly signup is now 2025-02-28. `npm test` passes (6 passed, 0 failed). I didn't add a test for the end-of-month case.

**Root cause:** `addMonths` in `src/renewal.mjs` called `setUTCMonth(month + 1)` while the day was still 31. JavaScript turned "Feb 31" into Mar 3, so the date overflowed into the next month.

**Fix:** `addMonths` now sets the day to 1 before changing the month. It then sets the day to the original day, or the target month's last day if that's earlier.

`renewalSchedule` calls `addMonths` once per renewal, counting from the start date. A 2024-01-31 signup on `--count 3` gives 2024-02-29, 2024-03-31 and 2024-04-30. A short month doesn't pull later renewals off the 31st.
